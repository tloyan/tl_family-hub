## Session Overview

**Sujet:** Application de gestion familiale — écosystème complet inspiré de Family Wall et Google Workspace, avec comme noyau la gestion des tâches quotidiennes par membre

**Objectifs:**
- Clarifier la vision globale du projet et son périmètre
- Générer un maximum de fonctionnalités (court, moyen et très long terme)
- Explorer les concepts structurants : distinction membres/foyer, profils, droits, groupes
- Identifier des idées innovantes au-delà des concurrents existants

### Contexte

**Motivations:**
- Frustration fonctionnelle : aucune app existante n'offre l'organisation de tâches souhaitée (simplicité + flexibilité, colonnes par membre, découpage matin/midi/soir, vues multiples, extensibilité)
- Frustration économique : coûts d'abonnement et devices physiques prohibitifs
- Montée en compétences full-stack senior sur des technologies clés

**Stratégie de livraison:**
- MVP limité = gestion de tâches quotidiennes (colonnes par membre, tranches horaires, vues multiples) → livraison rapide, publication stores
- Extensions progressives = calendriers, listes de courses, gestion de repas, messagerie/visio familiale privée, cloud, localisation, et plus

## Technique 3 : SCAMPER — Résultats

**26 idées d'affinage et de transformation** en passant les concepts clés à travers 7 prismes.

### S — Substitute (Substituer)
- [#147] Substituer les menus par la conversation IA — l'IA EST l'interface principale
- [#148] Substituer les rappels par l'action contextuelle — la bonne info au bon moment
- [#149] Substituer "tâche" par "rituel" comme concept mental — vocabulaire positif

### C — Combine (Combiner)
- [#150] Dashboard mural + Vue contextuelle + Mode kiosque = une expérience cohérente
- [#151] Rétro hebdo + Stats équipe + Résumé IA = amélioration continue data-driven
- [#152] Profil préférences + Fiche médicale + Consignes babysitter = "Fiche Membre" unifiée
- [#153] Rotation tâches + Équité IA + Capitaine enfant = répartition intelligente et valorisante

### A — Adapt (Adapter)
- [#154] Interface adaptée par profil d'âge (enfant 5-7 / 8-12 / ado / senior)
- [#155] Gamification comme calque optionnel activable par famille
- [#156] Notifications personnalisables par membre (off / essentiel / complet)
- [#157] Fiche Membre à visibilité variable par cercle (parent voit tout, babysitter voit l'essentiel)
- [#158] Granularité IA par zone avec presets simples (minimale / modérée / maximale)
- [#159] Personnalisation progressive — defaults intelligents, affinement au besoin

### M — Modify / Magnify (Modifier / Amplifier)
- [#160] Rituels imbriqués — sous-rituels au sein de rituels parents
- [#161] MVP réduit au noyau absolu — rituels + colonnes + validation uniquement
- [#162] Amplifier la mémoire familiale — timeline historique sur des années

### P — Put to other uses (Autres usages)
- [#163] Rituels comme manuel d'intégration pour nouveaux membres
- [#164] L'app comme outil thérapeutique familial (données objectives pour discussions)
- [#165] Protocoles d'urgence généralisés à toute situation structurée

### E — Eliminate (Éliminer)
- [#166] Éliminer la distinction tâche/rituel pour l'utilisateur — auto-détection par l'app
- [#167] Éliminer les permissions manuelles dans 90% des cas — presets par rôle
- [#168] Éliminer l'onboarding long — 2 questions puis usage progressif

### R — Reverse / Rearrange (Inverser / Réorganiser)
- [#169] Inverser le flux — les enfants proposent, les parents valident
- [#170] Pull vs Push — l'info attire plutôt qu'interrompt (calm technology)
- [#171] Navigation par moment plutôt que par fonctionnalité ("Ce matin", "Cette semaine")

### Architecture anticipée
- [#172] Entités métier anticipées dès le MVP — multi-foyer, 5 cercles, graphe familial en DB même si non exposés en UI

## Principes architecturaux clés

### 1. Architecture anticipée, UI progressive
L'architecture de données est complète dès le MVP (multi-foyer, cercles, graphe). L'UI expose progressivement les fonctionnalités au fil des versions. Pas de migration douloureuse, pas de dette technique.

### 2. L'IA est l'interface, pas un module
L'app est une conversation. Les menus sont un fallback. Tout ce qui est faisable par boutons est faisable par voix/texte.

### 3. Presets intelligents, personnalisation pour les exceptions
Pas de configuration complexe au démarrage. Des defaults sensés par rôle/cercle. La personnalisation se découvre progressivement quand le besoin émerge.

### 4. Modules activables par foyer
Chaque famille construit SON app en activant les modules pertinents. L'interface ne montre que ce qui est activé.

### 5. Gamification optionnelle et saine
La gamification est un calque qu'on ajoute par-dessus le core, pas intégrée au core. Jamais imposée, jamais de dark patterns.

### 6. Calm technology
L'app attire l'attention plutôt qu'interrompre. Navigation par moment. Information contextuelle. Notifications respectueuses.

3. **Rituels > Tâches** — le mot "rituel" évoque le positif, le rythme de vie. C'est le concept central, pas les "tâches".

4. **Architecture anticipée** — les entités métier doivent être prêtes pour multi-foyer, cercles, graphe dès le MVP, même si l'UI ne les expose pas encore.

5. **Personnalisation progressive** — defaults intelligents au démarrage, affinement au besoin. Jamais de configuration complexe d'entrée.

6. **Business model éthique** — monétiser les coûts réels (stockage, IA), pas les fonctionnalités relationnelles. Plafond à 10€ pour tout.
